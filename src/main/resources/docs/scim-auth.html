SCIM Authentication

Authentication Model

This SCIM service authenticates every request with an HTTP Bearer token. There is no interactive OAuth 2.0 flow. Credentials are issued by the SCIM service administrator and must be configured manually in the SCIM client. Three credential styles are accepted.

Header Format

Authorization: Bearer <token>
Content-Type: application/scim+json

Credential Styles

Style Shape Tenant handling Expiry
Static shared secret Opaque string issued by the administrator Not tenant-scoped. Tenant attributes in the request body are honoured as sent. None. Rotate manually.
Tenant token base64url(tenantId).base64url(secret) Tenant is taken from the token. Tenant attributes in the request body are ignored. None. Rotate manually.
Tenant JWT Signed JWT (HS256), three base64url parts Tenant is taken from the JWT header. Tenant attributes in the request body are ignored. Mandatory exp claim.

Tenant JWT

The JWT must be signed with the HMAC-SHA256 secret shared between the administrator and your identity provider. The service identifies the tenant and the signing key from the JWT header, verifies the signature, and only then reads the claims.

Header (all fields required):

{
  "alg": "HS256",
  "typ": "JWT",
  "kid": "<key id issued by the administrator>",
  "tid": "<your tenant id>"
}

Payload:

{
  "iss": "<your identity provider>",
  "sub": "scim",
  "iat": 1760486400,
  "exp": 1760490000,
  "jti": "<unique token id>"
}
Claim Required Rule
alg (header) Yes Must be exactly HS256. none and asymmetric algorithms are rejected.
kid (header) Yes Key id supplied by the administrator. Several key ids may be active during rotation.
tid (header) Yes Your tenant id. Letters, digits, ., _, -, at most 64 characters.
exp Yes Unix seconds. Expired tokens are rejected, with a small clock-skew tolerance.
nbf No If present the token is rejected until this time.
iss Conditional Must match the issuer registered for your tenant, if the administrator has configured one.
tid (payload) No If present, must equal the header tid.

Example request:

GET {{BASE_URL}}/scim/v2/Users
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCIsImtpZCI6ImtpZC0yMDI2YSIsInRpZCI6InRlbmFudC0wMDEifQ.<payload>.<signature>

Token Rules

  • A token must be sent on every request; there is no session.
  • Tokens and secrets are case-sensitive and must be kept confidential.
  • Transport must be HTTPS.
  • Rotate a token or signing secret immediately if compromised. For JWT, rotation is done by introducing a new kid; the old one is retired by the administrator afterwards.
  • For tenant-scoped credentials the tenant is derived from the credential; any tenant attributes in the request body are ignored, and PATCH operations targeting the tenant extension are dropped.
  • All authentication failures return 401 Unauthorized with a SCIM error body. The response does not indicate whether the tenant, key or secret was the cause.
